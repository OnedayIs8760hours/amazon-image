# 提示词模板梳理

> 梳理范围：`src/` 中所有会进入 LLM / 图像模型的文本模板、拼装函数与守卫规则。
> 结论先行：项目里没有单一的「提示词文件」，实际是 **4 层拼装 + 2 套独立提示**（Agent 对话、运维用「复制给 LLM」）。

---

## 一、整体结构

| 层 | 由谁生成 | 产物 | 代码入口 |
| --- | --- | --- | --- |
| ① 规划器系统提示 | 应用拼装后发给文本 LLM | `imagePlans[] / aPlusPlans[]` JSON | `src/lib/listingPlannerApi.ts` |
| ② 计划内提示词 | 规划器 LLM 自己写 | 每个槽位的英文 `prompt` / `negativePrompt` / `seriesStyleGuide` | schema 约束（同文件） |
| ③ 图像提示词装配 | 前端按用户选择拼接 | 最终发给图像模型的单一 prompt | `src/lib/listingPlanner.ts` |
| ④ 调用护栏 | 图像 API 适配层 | 「禁止改写 + 输出分辨率」尾注 | `src/lib/imageApiShared.ts`、`src/lib/agentApi.ts` |

另有两套不属于上述链路的提示：

- **Agent 助手提示**：`src/lib/agentApi.ts`（多轮对话 + 工具调用）。
- **运维提示**：`src/components/SettingsModal.tsx:202`（让外部 LLM 生成自定义服务商 JSON），与 `docs/custom-provider-llm-prompt.md` 是同一份文本的两个副本。

### 调用链

```text
用户粘贴 Listing 文案 / 填表单 / 传产品图
        │
        ▼
callAmazonPlannerApi()                         ← ① 系统提示 + ③ JSON 输出要求
  ├─ listingPlannerApi.ts:519  Listing 指令
  ├─ listingPlannerApi.ts:553  A+ 指令
  ├─ amazonKnowledge.ts        Listing / A+ 知识参考材料
  └─ 用户输入文本 :623          （Listing 原文 + 表单事实 + 参考图）
        │
        ▼  严格 JSON（schema / json_object）
normalize*()                                   ← 归一化、截断、语言过滤
        │
        ▼
AmazonPlanner 选中某个槽位
  └─ buildAmazonPlanPrompt / buildAmazonAPlusPlanPrompt   ← ③ 装配（风格 / 密度 / 负向 / 守卫）
        │
        ▼
store.submitTask()                             ← 追加隐藏风格参考图（最后一张）
        │
        ▼
callApi() / openaiCompatibleImageApi()         ← ④ 禁止改写护栏 + 分辨率要求
        │
        ▼
图像模型
```

## 三、图像提示词的拼装顺序与优先级

`formatPromptBlock`（`listingPlanner.ts:311-324`）固定按此顺序用空行拼接，空段自动跳过：

```text
1. prompt                    ← 规划器写的英文画面描述（含可见文案）
2. selected style block      ← 仅当附了风格参考图；明确「最高优先级」
3. series style guide        ← 标题会变成「(lower priority than the selected visual style)」
4. layout density            ← rich / minimal
5. Negative prompt:          ← 负向词没有独立字段，作为正向 prompt 的一段
6. STYLE_REFERENCE_GUARD     ← 最后一张图=隐藏风格板的说明
```

**优先级（从高到低）**

| 级别 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 产品事实 / 必须出现的可见文案 | 任何风格都不得改写 |
| 2 | 选中风格（Selected visual style） | 覆盖系列风格指南中的冲突项 |
| 3 | 系列风格指南（seriesStyleGuide） | 只保证一致性与事实连续性，不含调色/字体/氛围 |
| 4 | 信息密度（density） | 控制标注数量与留白 |
| 5 | 负向提示词 | 最后兜底排除 |

**注意点**

- 负向词被拼进**正向** prompt（多数图像 API 无独立 negative 字段），因此负向词是自然语言句子更稳，不要堆关键词。
- **主图不注入**系列风格（`AmazonPlanner.tsx:506` 传 `null`）：主图必须纯白底，也不注入密度与风格守卫（`styleReferenceAttached=false`）。这是有意的，但代码里没有注释说明。
- 隐藏风格参考图在提交时被追加为**最后一张**输入图（`store.ts:2207-2219`），主图槽位会被剥离该字段（`store.ts:128`），UI 中不展示（`store.ts:4107`）。

## 四、语言与格式约定

| 字段 | 语言 | 校验位置 |
| --- | --- | --- |
| `label` / `planMarkdown` | 简体中文 | 仅靠 schema description |
| `prompt` / `negativePrompt` / `seriesStyleGuide` | 英文 | 仅靠 schema description（负向明确禁止中文） |
| 图中可见文案 | 目标市场语言 | `normalizeOnImageCopy` 硬过滤 |
| `textTitle` / `textBody`（A+） | 目标市场语言 | 同上 |

| 站点 | 可见文案语言 | 是否允许 CJK |
| --- | --- | --- |
| US | US English | 否 |
| JP | Japanese | 允许日文，**不允许简体中文** |
| DE / FR / IT / ES | 对应语言 | 否 |

同一套语言规则目前有 **4 处**独立表述：`buildMarketplaceInstructionBlock`、`buildFieldLanguageRules`、`getVisibleCopyLanguageRule`、`localGuidance`（见问题 4）。

## 五、发现的问题（按影响排序）

### 1. 非 DeepSeek 规划器会丢掉用户手填的产品事实 —— 中

`listingPlannerApi.ts:759-765`：

```ts
userProductFacts: isDeepSeekPlannerProfile ? buildUserProductFactsText(options.baseDraft) : '',
```

只有 DeepSeek 分支会把 `color / material / packageIncludes / audience / forbidden` 拼进请求；其他支持图像的模型只从指令里拿到 `category`（Listing）/`brand`（A+）。表单里填的「不要出现」「包装清单」对非 DeepSeek 用户等于没填。

建议：`buildUserProductFactsText` 对所有 profile 都传，DeepSeek 只是额外加纯文本守卫。

### 2. 手工草稿模板是死代码 —— 中

`amazonPrompt.ts` 的 `AMAZON_IMAGE_PRESETS`（6 种图型 guidance）、`buildAmazonPrompt`、`getAmazonComplianceChecks` 全项目无引用，只有 `AmazonPromptDraft` 等类型被 3 个文件 import。

建议：要么接回 UI（作为「不调 LLM 直接出图」的降级路径），要么把类型迁到 `types.ts` 后删除模板函数，避免后人误以为它在生效。

### 3. 禁止改写前缀重复定义 —— 低

`agentApi.ts:779` 与 `openaiCompatibleImageApi.ts:23` 两份 `PROMPT_REWRITE_GUARD_PREFIX`，文案完全一致。

建议：上提到 `imageApiShared.ts`，与 `appendOutputResolutionToPrompt` 同处。

### 4. 市场语言规则四套写法 —— 中

四处各自维护「可见文案用什么语言 / 禁什么字符」，改动时极易漏改（例如 `getVisibleCopyLanguageRule` 里「never include Chinese or Japanese」的强约束，`buildFieldLanguageRules` 就没有对应表述）。

建议：`amazonMarketplaces.ts` 增加 `getVisibleCopyRule(config)` 单一函数，其余三处引用它。

### 5. `prompt` 里的中文没有后置校验 —— 低

`normalizeOnImageCopy` 只清洗「可见文案」字段，不对 `prompt` / `negativePrompt` 做 CJK 检查；schema 的 description 是软约束，模型仍可能写进中文。

建议：归一化时加一道 `assertEnglish(prompt)`，命中则记录告警或剥离。

### 6. 知识库存在两份来源 —— 中

`docs/knowledge/*.md` 是人工知识原文，`amazonKnowledge.ts` 是手写摘要，两者没有生成关系。改 md 不会改提示词，反之亦然。

建议：加一个构建期脚本从 md 生成 notes，或在 `amazonKnowledge.ts` 顶部注明「以 docs/knowledge 为准，改动需同步」。

### 7. Listing / A+ 两套指令高度平行 —— 低

`buildListingPlannerInstructions` 与 `buildAPlusPlannerInstructions` 有 6 条近乎逐字重复（市场块、参考图事实规则、planMarkdown 要求、seriesStyleGuide 要求、不生成风格板、字段语言规则）。

建议：抽 `buildPlannerBase()`（市场块 + 事实规则 + 语言规则 + 风格板禁令），两个变体只写差异段。

### 8. 回归测试依赖字符串片段 —— 低

`listingPlanner.test.ts` 用 `toContain('Series style guide:')` 之类的断言，改一句文案就红。

建议：改为断言**段落顺序**和**关键段存在**（用一个 `sections` 数组断言），或在 `formatPromptBlock` 抽出结构化中间产物再测。

### 9. 提示词常量分散、无版本 —— 低

英文模板散在 5 个文件，没有统一导出、没有版本号或 A/B 开关，调参只能改源码重新构建。

建议：集中到 `src/lib/prompts/`（见下节），按 `PROMPT_VERSION` 打标。

## 六、可选的重构目录

```text
src/lib/prompts/
  shared.ts            # 禁止改写、分辨率、语言规则、CJK 校验
  knowledge.ts         # 由 docs/knowledge 生成的参考材料
  planner.base.ts      # 市场块 + 事实规则 + 语言规则 + JSON 要求
  planner.listing.ts   # Listing 差异段 + schema
  planner.aplus.ts     # A+ 差异段 + schema
  image.assembly.ts    # formatPromptBlock / guard / density
  agent.ts             # AGENT_* 常量与工具描述
  index.ts             # 统一导出 + PROMPT_VERSION
```

每个模块只导出纯函数（输入 options → 字符串），配合快照测试，文案改动可见、可审。
